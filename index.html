How “Ask TARA” answers a question

  1. A traveler asks“Plan two days in Laguna with hot springs and local food.”
  2. The model reads itA self-hosted Qwen3-8B fills in a fixed JSON intent form, and nothing more.
  3. The backend looks it upPlaces, prices, hours, and routes come from PostgreSQL and PostGIS.
  4. The planner builds the tripStops are scheduled around opening hours, meals, and hotel stays.
  5. The answer streams backWith driving routes and jeepney or tricycle directions.

Early versions sometimes described places that didn't exist. Splitting the work this way fixed it: the model only interprets the request, and every place, price, and route in the answer comes from our database.

  • Built data imports that clean, deduplicate, and load Laguna places, foods, products, and transit routes into PostgreSQL/PostGIS, with a dry-run check before anything is written.
  • Created plan-quality metrics, a batch sweep of the planner, and an evaluation harness that compares language models on labeled conversations.
  • Added integrity migrations and a GitHub Actions pipeline that rebuilds the database and runs 35 SQL test suites on every pull request.

iHelp

A Grammarly-style checker for accounting spreadsheets in Google Sheets. Side project, 2026.

Built on my own. It scans the sheet while its sidebar is open, flags likely errors, and explains each one in accounting terms with a suggested fix.

  • TypeScript
  • Google Apps Script
  • Gemini API
  • Vitest
  • esbuild

How iHelp checks a sheet

  1. The sheet is readEvery cell's value and formula, while the sidebar is open.
  2. Tables are recognizedJournals, trial balances, depreciation schedules, VAT registers, and BIR worksheets.
  3. 19 checks runSpreadsheet risks, accounting rules, and Philippine tax computations.
  4. Errors are flaggedEach with a plain explanation, and a Fix now button where the fix is certain.

A trial balance that's off is traced, too: if the difference equals one balance, it was left out or doubled; if half of it does, it's in the wrong column; if it divides by 9, two digits were probably swapped.

  • Wrote checks for unbalanced journals, a trial balance that disagrees with its journal, totals that don't foot, sums that miss new rows, numbers typed over formulas, circular references, and VAT, withholding tax, BIR 2307, and 2550Q computations.
  • Made “Fix now” safe: it writes only if the cell hasn't changed since the scan, never creates a circular reference, refers to the rate cell instead of typing a number, and can be undone.
  • Added an Ask tab powered by Gemini that answers questions about the open sheet and can insert a suggested formula, falling back to a lighter model when the main one is overloaded.
  • Covered it with 226 unit tests and an evaluation harness; it caught all 36 errors planted in the test sheets.

DefenSync

Android app that finds a thesis defense time the student, adviser, and every panelist can make. Team project, 2026.

Developer on a two-person team. I built the Calendar screen and the availability syncing in the PHP API.

  • Kotlin
  • Jetpack Compose
  • Ktor
  • PHP 8
  • MySQL

How the app finds a defense time

  1. Everyone marks free hoursStudents and professors set their usual weekly availability.
  2. Ranges are mergedEach person's overlapping free times are joined, to the exact minute.
  3. Shared windows are foundThe app intersects every member's free time.
  4. Slots are suggestedEvery 3-hour block that fits the whole panel.
  5. The defense is confirmedOnce every member accepts the proposed time.
  • Made default-schedule edits carry over to each defense group, but only where the group copy still matches the old default, so changes someone made for a specific group are never overwritten. The update runs in one database transaction.
  • Built the Calendar screen and a reusable initials avatar in Jetpack Compose.
